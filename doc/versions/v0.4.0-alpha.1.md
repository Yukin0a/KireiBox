# KireiBox 0.4.0-alpha.1

## Changes

- Dashboard layout JSON v3 stores widget height in independent 8dp steps,
  migrates v1/v2 positions, previews surrounding layout while resizing and
  enforces per-widget minimum/default/maximum heights.
- Added bottom-left circular style controls, a clearer two-segment arrange
  mode, small-screen spotlight constraints, three-item Recent Games scrolling,
  new overview/favorites/library/trend styles and distinct-games-launched
  trends.
- Database v19 records successful engine launches separately from duration.
  Failed starts are excluded and repeat launches of one game on one local day
  count once.
- Added the optional KRKR startup single-button information policy. Separate
  save directories now default off; explicit prior choices are preserved.
- Added a default-on, KireiBox-styled built-in file browser with All Files
  permission recovery and a system SAF/SD-card fallback. A shared storage node
  now backs SAF and direct-file scanning, detection, preflight, title probing
  and per-game KRKR settings.
- Version is 0.4.0-alpha.1 / versionCode 6. Database schema is v19.

## Architecture share

Measured over 13,445 nonblank Kotlin/Java lines in `:app` and
`:core-yukihub`, excluding the four native engine implementations:

| Layer | Lines | Share |
|---|---:|---:|
| KireiBox UI and shell | 5,119 | 38.1% |
| Four-engine launch glue | 2,694 | 20.0% |
| YukiHub data/scanner/metadata/settings core | 5,632 | 41.9% |

Within the non-UI lower layer, YukiHub core is 67.6% and launch glue is 32.4%.
RinneMobile remains an interaction-policy reference only: there is no Rinne
module, database, scanner, cover queue or artifact in the runtime graph.
YukiHub remains the single data, settings and scanning core; `StorageNode`
adds one shared path for direct files and SAF documents rather than a second
scanner.

## Rollback

The preserved 0.3.0-alpha.2 APK can open the v19 database through the supported
v19→v18 downgrade path. The added `launched_at` column and dashboard-v3-only
fields do not overwrite game files. Back up app data before downgrading any
alpha build.

## Tests

- `gradlew.bat test`, `:app:lint`, `:app:assembleDebug` and
  `:app:assembleRelease` passed. Debug/Release ran 178 JVM tests in 42 suites
  with 0 failures, 0 errors and 0 skipped. Lint reports 0 errors and 318
  inherited warnings.
- JVM coverage includes dashboard v1/v2→v3 migration, 8dp snapping, height
  bounds and collision-free packing; distinct successful launches across
  game/day/time-zone boundaries; KRKR single-button/30-second policy
  boundaries; and direct-file/SAF-compatible shared engine detection.
- Pixel 8 API 37 emulator checks covered 320×568dp, 360×640dp, 393×852dp,
  768×1024dp and 1024×768dp. They covered small-screen spotlight typography,
  independent play placement, editor controls and live reflow, three-game
  recent scrolling, compact/wide layouts and the new style variants.
- The final Release was reinstalled and reported versionCode 6,
  versionName 0.4.0-alpha.1 and primary ABI arm64-v8a. The built-in browser was
  checked in light/dark themes, its All Files permission explanation resumed
  the pending action, the SAF fallback opened DocumentsUI, and the final root
  breadcrumb displayed `内部存储`.
- ATRI launched through `com.akira.tyranoemu.remote.Kirikiroid139`. Its
  `:kirikiri2` process remained active for 216 seconds at the recorded check,
  with no fatal exception, native abort or `KrFontScaleManager` warning.
  Runtime logs confirmed reads/writes under
  `/storage/emulated/0/Download/gal/ATRI/savedata`.
- APK checks passed arm64-v8a-only contents, 4-byte zip alignment, APK
  Signature Scheme v2 and `sf.sf2` exclusion.
- A real game containing a translator-group single-button startup dialog was
  not available, so the dialog rule is covered by the engine policy test seam
  but remains unverified against that kind of game. Physical Pixel 8,
  Huawei/HarmonyOS and Android 14 hardware remain unverified.

Responsive, editor, permission, browser and ATRI screenshots are stored under
`artifacts/screenshots`; the selected ATRI runtime evidence is stored under
`artifacts/logs`.
