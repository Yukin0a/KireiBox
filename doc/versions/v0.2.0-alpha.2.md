# KireiBox 0.2.0-alpha.2

## Background

This release narrows KireiBox to a Compose presentation shell, a YukiHub-owned
catalog/scanner/metadata/settings core, four bundled engines (Kirikiri,
ONScripter, Tyrano and Artemis), and Android package cards. PSP, GameHub,
RPGMaker, Ren'Py, Godot and the old global font patch are not launch targets.

## Database/API

- Main database: `kireibox.db`, schema v18.
- Legacy `kireibox_demo.db`: one-time migration input only.
- Public domain boundary: `YukiCoreFacade`, `GameRepository`, `GameScanner`,
  `YukiMetadataService` and `YukiSettingsStore` in `:core-yukihub`.
- Gradle runtime graph: `:app` -> `:core-yukihub` + `:engine`; no RinneMobile
  module or artifact is linked.
- Application ID: `com.kireibox.app`.
- SDK: minimum 26, target 33, compile 36.
- Release ABI: arm64-v8a only.

## UI and interaction

- Replaced the fixed 2x2 home grid with one editorial hero, weighted play-time
  metrics and a recent-games rail; the launch control is again a purple triangle.
- The shell now uses measured system and Dock insets. Phone content scrolls
  between the fixed title and Dock, while 768x1024 and wider windows use a
  two-pane home layout. The library is fixed at two columns below 600dp and
  uses adaptive 160/168dp columns on tablets, capped at 1200dp content width.
- The phone home body now owns only the measured height remaining below the
  title (`weight(1f)`), uses a compact 38%-height hero, and keeps an additional
  20dp scroll-end gap. At 393x852dp the recent-game card is fully visible before
  the Dock with no initial scroll.
- A game-card tap opens a continuous 88%-height action sheet with decoded,
  human-readable storage locations. Kirikiri settings open on a dedicated,
  Dock-free full-screen page with a fixed save action.
- Long-pressing a game enters a reduced-motion-aware +/-0.7 degree edit mode.
  Removal hides the YukiHub catalog row rather than deleting files, and a
  five-second notification can restore the original list position.
- Cover lookup is ranked by YukiHub's title scorer. High-confidence matches are
  applied automatically; ambiguous matches stay in a responsive picker until
  the user selects a candidate and confirms it.
- Light and dark palettes animate between states. Light mode uses the darker
  purple `#5B45C7`, opaque circular controls and a coordinated lavender notice.
- Cover decoding is sampled and backed by a process LRU cache capped between
  8 MiB and 32 MiB instead of decoding full-resolution images repeatedly.
- Settings includes a non-networking GitHub Releases placeholder marked as
  under development.

## Architecture share

Measured over nonblank Kotlin/Java lines in `:app` + `:core-yukihub`, excluding
the four native engine implementations:

| Layer | Lines | Share |
|---|---:|---:|
| KireiBox UI and shell | 3,158 | 30.0% |
| Four-engine launch glue | 2,580 | 24.5% |
| YukiHub data/scanner/metadata/settings core | 4,799 | 45.5% |

Within the non-UI lower layer, YukiHub core is 65.0% and launch glue is 35.0%.
All catalog, scan, metadata, preferences and play-session calls now enter through
YukiHub-owned APIs. RinneMobile runtime dependencies remain zero; the launch
glue is engine compatibility code and remains the next reduction target.

Physical source lines across `app`, `core-yukihub` and `engine` (excluding
`build`, `.cxx` and generated output) are:

| Language/resource class | Lines | Share |
|---|---:|---:|
| Kotlin | 10,239 | 38.8% |
| Java | 13,866 | 52.6% |
| C/C++ headers and sources | 583 | 2.2% |
| Gradle and text resources | 1,676 | 6.4% |

| Module | Lines | Share |
|---|---:|---:|
| `app` | 7,448 | 28.3% |
| `core-yukihub` | 4,962 | 18.8% |
| `engine` | 13,954 | 52.9% |

The active backend path is Compose/ViewModel -> `YukiCoreFacade` and
`GameRepository` -> the four-engine launch bridge -> bundled engine Activity.
No Rinne module, artifact, repository or metadata task store is in that path.

For ancestry auditing, an ordinal exact-line comparison against
`RinneMobile-main/app/src/main/java` found 8,054 / 10,537 nonblank lines (76.4%)
with a match; after excluding imports, short syntax and lines under 16 characters,
4,787 / 7,070 lines (67.7%) match. This is textual similarity, not a runtime
dependency: the comparison repository itself embeds many YukiHub classes, and
common Kotlin/Java syntax also counts. Launch glue remains the main high-overlap
area (96.8% exact-line membership) and is the next migration target.

## Rollback

`SingleCoreMigration` creates an app-private snapshot under
`files/migration-backups/alpha1-<timestamp>` before opening or writing the v18
database. The previous APK remains at
`apk/KireiBox-0.1.0-alpha.1-arm64-v8a.apk` (61,565,766 bytes,
SHA-256 `2D7978D965A06AD328DBA8D3F3BD5D34A0DA70CF7DC7DDD5988CB26C9CEDA6C8`).
Downgrading still requires restoring a compatible database snapshot; Android 14
and HarmonyOS 2 downgrade behavior has not been device-verified.
